# UPGRADE-001：升級、換機與資料恢復

## Release candidate 升級

1. 在舊 build 建立配對、聊天、照片、Moment、回應、答案、名稱、狀態與可用的離線待送項目。
2. 不清除 App 資料，直接安裝 release candidate。
3. 確認帳號與 relationship 不重建；遠端內容數量、正文、照片、時間、順序與關聯一致。
4. 恢復網路後，舊待送項目只送達一次且順序正確。
5. 舊版與新版若可能同時存活，驗證向後相容讀寫；不相容時必須阻擋發布並有明確 rollout 計畫。

## 換機／重裝

1. 使用第二支已清除本機狀態的真實 iPhone，以同一測試帳號登入。
2. 不持有或操作舊手機、不掃描換機碼、不手動備份且不重新配對，恢復本人可存取的 relationship 與完整遠端歷史。
3. 確認先出現帳號／relationship 與近期內容，舊聊天／Moment 可分頁繼續載入，照片進入可見範圍後可讀；單一失敗可重試且不清空已恢復內容。
4. 逐類核對數量、時間、順序、照片可讀性與 Moment／問答／聊天關聯。
5. 核對「資料與恢復」的同步狀態、待送數量與最近成功同步時間，不將本機 Outbox 誤標為已同步。
6. 新、舊兩機同時登入時，在其中一機執行一般「登出」；預期只清除該機 local session，另一機維持登入及相同 relationship／共同資料／個人封存。已登出裝置重新以同一帳號驗證後須恢復原資料且不重新配對。依 PD-044，MVP 不宣稱可從另一台裝置遠端撤銷遺失裝置。
7. 再執行一次刪除 App 後重裝，重複驗證。
8. 明確記錄仍只存在原遺失裝置 Outbox 的內容不保證恢復，UI 不得把它標成已同步。

## Database／Storage restore drill

- 本清單只驗證換機／重裝後的產品恢復體驗；完整雲端事故、刪除重播、signed manifest 與異區冷重建另依 [`DR-001`](disaster-recovery.md) 執行。
- 從同一恢復點還原 database 與 Storage，依 object identity、byte size／checksum 與產品引用清單核對 metadata、實體 object 與引用一致。
- 記錄可恢復範圍、資料時間點與無法恢復的缺口；「備份功能已啟用」不算通過。

任一靜默清空、重複、錯序、關聯斷裂、照片缺失或要求使用者重新配對都阻擋發布。
