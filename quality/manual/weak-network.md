# NETWORK-001：弱網、離線與重連

## 前置條件

- 兩支已配對真實 iPhone，使用可回收測試內容。
- 明確記錄本版本哪些內容已承諾持久 Outbox；尚未實作的能力標記 `NOT_APPLICABLE`，不得宣稱通過。

## 步驟與預期

1. A、B 同時離線各送出三則正式文字訊息；輸入框只在 Outbox 保存成功後清空，每則立即顯示但不得標示為已同步，強制結束再重開後待送資料仍存在且原輸入順序不變，不得出現輸入清空但沒有泡泡的情況。
2. A 由 Wi-Fi 切換行動網路，B 做短暫 Wi-Fi 中斷；恢復後自動或由明確重試送達，另一支正在前景的手機須即時顯示，不得要求重啟 App。
3. 同一 stable client ID 重試不產生重複；多筆內容維持可預期 FIFO／server order。
4. App 在背景、前景恢復與離線冷啟動時先由唯讀快照回到原 relationship，不等待遠端逾時；不得並行重送同一項目，快照也不得讓已失效的遠端寫入繞過 RLS。
5. 已登入且已有 relationship 快照時，離線冷啟動仍顯示「今天／對話／我們」主畫面及離線提示；不得自動開啟帳號設定或其他 modal。
6. 舊 relationship、closing／archived relationship 的待送內容不會誤送到目前伴侶。
7. 保持離線直到有限嘗試停止；UI 保留傳送失敗與明確重試，不無限輪詢。恢復網路後點重試只送達一次。
8. UI 清楚區分傳送中、失敗、已同步；本機待送內容不得標示為已備份。
9. 兩支手機至少先在線成功載入一次對話；離線強制結束再開啟時仍顯示最近同步的聊天內容與待送訊息，不得顯示成全新空聊天室。恢復網路後以遠端內容校正且不重複。
10. 兩支手機至少先在線成功載入一次「今天」；離線強制結束再開啟時，最新 Moment、照片、雙方稱呼及未過期狀態先由唯讀快照顯示，不得長時間只顯示載入畫面。已過期狀態不得因離線快照重新出現；恢復網路後不用重啟 App 即以遠端 RLS 結果校正。
11. 成功登出後，前一個 user 的 relationship、聊天快照與待送內容不會顯示於下一個登入身分；遠端確認 relationship 已失效或改變時亦不保留舊關係聊天資料。

## W10 加驗（尚未執行）

1. A 離線後依序送出文字 T1、照片 P1、文字 T2；三項都在 Outbox 保存成功後才清除 composer，並以待送狀態按原順序顯示。
2. 保持離線強制結束 App 再重開；T1、P1、T2 與 P1 的本機照片資料仍存在且順序不變，不得把任一項標成已同步。
3. 恢復網路；B 最終只收到一次 T1→P1→T2，P1 可開啟，前一項失敗或重試時後一項不得超車。A 的 Outbox 成功清空後，本機待送照片檔也應清除。
4. 在 P1 上傳完成但回應遺失的條件重試；相同 stable client ID 不得建立第二則訊息或第二份 Storage object。

## 通過證據

記錄每輪網路轉換、force-quit 時點、送達次數、順序與 Outbox 最終狀態；W10 另記錄 T1／P1／T2 的 stable client ID 前 8 碼與照片暫存檔清理結果。漏送、重複、錯序、無限重試、殘留照片或送錯 relationship 都阻擋發布。
