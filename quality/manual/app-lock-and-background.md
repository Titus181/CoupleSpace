# LOCK-001：App Lock、背景與重新啟動

目前實作是 opt-in：帳號設定開啟後，App 進入 inactive 或 background 立即以不含私密內容的畫面遮蔽；回到 active 時以 Face ID 或裝置密碼驗證。取消、失敗或無法驗證時必須維持遮蔽，不登出、不解除配對，也不變更待送內容。

## 前置條件

- 使用一支已設定裝置密碼與 Face ID 的真實 iPhone；以可安全刪除的測試帳號登入，並完成一段 active relationship。
- 建立可辨識的測試資料：一則聊天、含照片的 Moment、以及一則尚未送出的 Outbox 項目；記下登入帳號前 8 碼、relationship 前 8 碼與待送項目的文字／數量。
- 測試通知時只用泛化測試通知；不要在截圖、錄影或驗收紀錄中保存私密正文或真實身分。

## 執行清單

- [ ] **未啟用基線：** 保持「我們 → 帳號設定 → 使用 Face ID 或裝置密碼解鎖」關閉，冷啟動 App。預期直接回到原本登入／配對／內容流程，沒有鎖定畫面或系統驗證提示。
- [ ] **啟用與立即遮蔽：** 開啟設定。預期立即只見「CoupleSpace 已鎖定」遮罩；聊天、照片、Moment 與答案不可見，按「解鎖」會出現 Face ID 或裝置密碼提示。
- [ ] **驗證成功：** 成功以 Face ID 或裝置密碼驗證。預期回到啟用前所在內容，登入帳號與 relationship 前 8 碼不變；既有待送項目仍只有原本一筆，未被重新送出或重複建立。
- [ ] **inactive／background：** 解鎖後依序觸發來電／控制中心等 inactive、回桌面進入 background，再回到 App。每次私密內容都必須先被遮蔽；回到 active 後只能在成功驗證後顯示。
- [ ] **取消、失敗與暫時不可用：** 在系統提示取消一次、以錯誤驗證方式失敗一次；如裝置可重現暫時鎖定／不可用，也執行一次。每一種結果都維持遮罩，顯示可理解狀態，且可按「解鎖」再次嘗試；不得登出、解除配對或改變待送項目。
- [ ] **冷啟動與鎖屏返回：** 保持啟用，強制結束後冷啟動；再鎖定裝置並解鎖後返回 App。兩者皆應在任何私密內容出現前要求驗證。
- [ ] **App switcher／背景與通知：** 在鎖定狀態與剛切到背景時檢查 App switcher snapshot；再於裝置鎖屏時檢查通知與背景畫面。不得可見聊天、照片、Moment、答案或其他私密正文。
- [ ] **關閉與偏好恢復：** 成功解鎖後關閉設定。預期內容立刻恢復且不再要求驗證；強制結束並冷啟動，確認仍維持關閉。重新開啟後再冷啟動，確認仍先遮蔽並要求驗證。

## 證據與阻擋規則

記錄 build、iPhone 機型／iOS、測試帳號與 relationship 的去識別前綴、每一項結果，以及不含私密內容的鎖定／App switcher 截圖。任何未驗證即顯示私密內容、無法安全退出、設定未持久化，或驗證導致 session、relationship、Outbox 改變，都使 `LOCK-001` 為 FAIL 並阻擋 G12 關閉。
